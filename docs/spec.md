# spec

言葉（テキスト・歌詞・台詞）を入力すると、手話/指文字/身振りの3Dモーションを生成し、**任意の3Dアバターの手・指・腕へリターゲット（流し込み）できる**モーション基盤ライブラリの仕様。

コード構成・レイヤ分離・技術スタックは `docs/architecture.md` を参照。ここに書くのはコードが説明できない仕様（データモデル・モードの線引き・retarget 指示形式・MVP スコープ）。

見た目の設計システム（DESIGN.md）は現時点では未作成。理由は「何ではないか」の項を参照（唯一の視覚要素である右上ワイプは利用側の演出であり、このライブラリの設計システムではない）。デモ/プレイグラウンドUI に着手する段で DESIGN.md を起こす。

## 何ではないか

- 「手話翻訳AI」ではない。手話は各言語の逐語置換ではなく、それ自体が文法・空間参照・表情/視線/間を持つ独立言語であり、完全な自動翻訳を名乗らない。
- 右上ワイプを合成する配信アプリではない。ワイプのデザイン・配置・配信画面への合成は、利用側（配信者・動画制作者）が行う。
- 特定のアバターアプリではない。特定アバターに固定されず、手・指・腕のモーションを配り、任意のアバターへ流し込めるライブラリにする。

ライブラリが担うのは、生成された手話/指文字/身振りモーションを、任意の3Dアバターの骨格へマッピング/リターゲットする層。

## 核

- **入力**: プレーンテキスト / 歌詞 / タイムコード付き歌詞 / 台詞。取り込み形式は SRT / VTT / LRC / プレーンテキストを想定。
- **出力**: アバター非依存の両手3Dモーション（手首・手のひら・指関節、必要に応じて腕・顔・体）。runtime が直接読む motion JSON と、エージェントが読める retarget 指示（後述）の両方。
- **プレビュー**: Three.js 上の簡易手モデル（左右の手）。
- **ライブラリ利用**: 好きな VRM / glTF / Three.js アバターへ手話/指文字/身振りモーションを流し込む。

## データモデル（最小中間表現）

アバターに依存しない中間表現として、以下を定義する。**不変の定義データ（プリセット motion・avatar profile）と、実行時に再生される motion/timing を分けて扱う**（定義とその再生処理を同じ構造に混在させない）。

- **skeleton**: 左右の手・手首・手のひら・指関節の構造定義。
- **pose**: 各関節の回転、手首位置、手の向き（1時点の姿勢）。
- **motion**: pose の時系列。
- **timing**: 開始時刻・終了時刻・ease・hold。
- **semantic label**: 単語/句/歌詞/身振り名などの意味ラベル。

確定スキーマは `schema/motion.schema.json`（v0.1.0）。motion は以下を必須で持つ。

- **category（言語区分）**: `jsl`（日本手話）/ `kana-fingerspelling`（かな指文字）/ `sign-like-gesture`（手話風身振り）。3区分は混ぜない。
- **provenance（監修状態）**: `unreviewed`（未監修）/ `reviewed`（監修済み）。`reviewed` は `reviewer` と `reviewedAt`（YYYY-MM-DD）が必須。
- 「手話」として扱ってよいのは `category=jsl` かつ `reviewed` のみ（`isReviewedSignLanguage`）。
- **回転の規約**: euler 角（度）`[x,y,z]`、intrinsic XYZ 順。右手のローカル軸で、x = 屈曲（正で指を曲げる／手首は掌屈）、y = ひねり（指の長軸まわり。正で回内）、z = 橈側偏位（正で母指側＝橈側へ倒す。手首は橈屈）。指によらず向きは固定で、「指を開く」向きは指ごとに符号が変わる（例: 示指は橈側へ開くのが正、小指は尺側へ開くので負）。
- **位置の規約**: `wrist.position` は meter、原点は演者の胸中央（胸骨）、+x = 演者の右、+y = 上、+z = 前方。範囲は ±10m（回転の ±360 とは別定義）。
- **左手は右手の鏡像として表す**: `left` に書く値は「右手と同じ規約で記述した値」で、左手に適用するときに鏡像変換する（位置 x と回転 y・z の符号を反転）。左右対称な動きなら left と right は同じ値になる。
- `rangeOfMotion`（avatar profile）も右手基準で、左手には鏡像として同じ値を使う。
- **timing の意味（再生）**: keyframe の `ease` / `hold` は「そのキーフレームから次のキーフレームへ向かう区間」に掛かる。`time`〜`time+hold` はそのポーズを保持し、`time+hold`〜次の `time` を ease（linear / ease-in = t² / ease-out = 1-(1-t)² / ease-in-out）で補間する。最初より前・最後より後は端のポーズを保持。`left`/`right` の片方しか書かれない手は、その手の指定があるキーフレームだけで補間し、一度も指定がない手は待機姿勢（胸の横で下ろす）。
- keyframes の `time` は厳密に昇順、`time+hold` は `duration` 以内（浮動小数誤差 1e-9 を許容）。`reviewedAt` は `format: date` で実在日付を検証する。左右は `left`/`right` キーのみ、手ごとに指関節15個すべて必須。

### avatar profile（アバター定義）

「このアバターでは、肩/肘/手首/各指がどのボーンか、可動域はどこまでか、初期姿勢をどう補正するか」を定義する。avatar profile は**アバターごとの不変の定義**であり、実行時 motion とは別に持つ。

- 必須: 左手・右手・指ボーン。
- 任意: 肘・肩・顔。
- 確定スキーマは `schema/avatar-profile.schema.json`（v0.1.0）。`capability`（`full`/`gesture-only`）、`bones`（VRM humanoid ボーン名等との対応）、`rangeOfMotion`（関節ごと・軸ごとの [min,max] 度）、`restPoseCorrection`（初期姿勢補正）を持つ。
- `full` は全指ボーン必須。`gesture-only` は指ボーン無しを許容する。
- 指ボーンが不足するアバターでは gesture mode のみ対応に落とす（フォールバック）。
- 可動域を超える指示は、意味を保つ範囲で腕位置を補正する（目標。Phase 1 の実装は、右手基準の可動域で各軸を clamp し、丸めた箇所を結果の `clamped` に記録するところまで。腕位置の補正は未実装）。
- retarget の適用順: 可動域 clamp（右手基準）→ 左手のみ鏡像変換 → `restPoseCorrection`（ボーン名一致）を加算。`gesture-only`（宣言、または全指ボーンが揃っていない）では指の回転を出力せず、手首/腕のボーンだけを返す。

### VRM 1.0 への適用規約（Phase 4a）

対象は **VRM 1.0 のみ**（拡張 `VRMC_vrm`、specVersion `"1.0"` / `"1.0-beta"`＝three-vrm が受け付ける版）。VRM 0.x・VRMC_vrm のない glTF・humanoid 定義が欠けた・ノード番号が不正（範囲外・負数・小数）なファイルは読み込まず、行ごとのエラーで返す（`src/avatar/glb.ts`）。ファイルはブラウザ内だけで処理し、アップロードしない。

- **profile の自動生成**（`src/avatar/vrmProfile.ts`）: humanoid のボーン名集合から生成。ボーン名の対応表は `samples/vrm1-humanoid.avatar-profile.json` を正本として再利用する。左右の手首（hand）は必須（欠ければエラー）。指ボーン30個が全て揃えば `full`、1つでも欠ければ `gesture-only`（欠けた名前を報告）。肩/肘（upperArm/lowerArm）・顔（head/jaw）は任意で、あるものだけ入れる。可動域は同表のもの。生成結果は既存スキーマ検証を通す。normalized humanoid は常に T-pose なので `restPoseCorrection` は出さない（A-pose の素のリグを直に扱う場合は profile に足せば retarget が加算する）。
- **座標系**: VRM 1.0 は +Z が正面、キャラクターの left が +X、+Y が上。演者座標（+x = 演者の右）とは x が逆なので、位置は x_vrm = -x_演者。胸中央（原点）= 両 upperArm の中点から 0.15m（×scale）下。scale = avatar の腕の長さ（上腕+前腕）/ 0.6m で位置を拡縮する。
- **腕は 2 ボーン IK**: wrist.position へ upperArm/lowerArm を回して手首を届かせる（肘は下・外・後ろ寄りに曲がる）。届かなければ腕を伸ばしきり、`unreachable` に記録する（ビューアは「手首が届かず腕を伸ばしきり(左/右)」と表示）。上腕・前腕の長さが 1e-4m 未満のアバターは IK できないので腕は書かない。**IK が有効な側では motion の `arm.shoulder/elbow` は適用しない（手首位置優先）**。profile の肘の可動域（x [0,145]）は絶対の屈曲角で、IK の結果と二重に効かせると手首が目標から外れるため。適用しなかった手は結果の `armOverridden` に記録する（ビューアは「肩/肘の指定は IK 優先で未適用(左/右)」と表示）。
- **euler の軸は解剖学の語で定義**（正本）し、VRM の軸へは手ごとの基底で写す。q = B · E(x, y, -z) · B⁻¹（B は T-pose の手の軸 -> VRM ワールド軸の右手系回転。橈屈 z の符号反転は基底を右手系にするため）。右手の B: X'(屈曲軸)=+z、Y'(指の長軸)=-x、Z'(手のひら法線)=-y。左手の B は x 反転した鏡像。左の値は retarget が右手規約から鏡像済み（y・z 反転）なのでそのまま左の B に通す。指・肩・肘はこの式（親のローカル軸が T-pose のままなので）。
- **手首の euler は「前腕の延長を基準にした手の向き」**: 基準 = 指が前腕方向、手のひら法線は「前・下寄り 45°」の基準ベクトルから前腕に直交する成分を取る（前腕が上でも下でも手のひらは前、母指は前腕が上なら正中線側・下なら外側。前腕が基準ベクトルと同軸になる向き、つまり前下 45° と反平行の後ろ上 45° 付近では法線が不安定になる特異点で、そこへ近づくと向きが跳ぶ。同梱モーションはどちらにも到達しないが、到達する motion では手の向きが跳ぶ）。手の向きはワールドで決めてから前腕の IK 回転を打ち消す（手のひらの向きを優先）。残る回転は前腕の長軸まわりの twist と swing に分け、**twist は lowerArm のローカル回転に載せ、hand ボーンには swing だけを書く**（hand に大きなひねりを残さない。world の手の向きは変わらない）。前腕が基準ベクトルと平行・反平行（同軸）の特異点では、前腕に直交化した軸へ退避して基底を直交・単位長に保つ。
- **初期姿勢**: T-pose 想定（normalized humanoid の rest 回転は単位）。A-pose の素のリグは `restPoseCorrection` で補正する設計だが、自動生成 profile は normalized 前提で出さない。
- 指ボーンは母指も同じ軸規約で曲げる（母指の解剖学的な軸の違いは未考慮）。

## モードの線引き（手話の正確性を誇張しない）

不正確な手話を「手話対応」と言い切ると逆効果になり得るため、モードを名前で明確に分ける。

- **字幕ワイプモード**: 字幕テキストを元に、かな指文字や簡単な身振りを出す。手話通訳とは呼ばない。UI/コード上のモード名は「指文字/身振り支援」等とし、「手話通訳」「手話翻訳」を名乗る文言は作らない。
- **指文字ワイプモード**: 固有名詞や短い語を指文字で表示する。
- **監修済み手話ワイプモード**: ネイティブ手話話者が確認した語彙・フレーズだけを使う。この段階から初めて「手話対応」と言える。
- **アバターリターゲット**: 好きな VRM / glTF / Three.js アバターへモーションを流し込む。ワイプ化そのものは利用側の演出。

**規律: 実手話モードと手話風身振りモードを混同させない。** 本物の手話支援として提供する段階では、必ず当事者・ネイティブ手話話者のレビューを前提にする。手話として正確に扱う語彙は、後から監修前提で追加する。

## エージェント向け retarget 指示

アバター自体もエージェントで編集できる時代を前提に、runtime が直接読む motion JSON だけでなく、**エージェントへの指示として使いやすい形式**も吐けるようにする。

- **機械可読**: JSON（runtime が直接読む motion データ）。
- **人間/エージェント可読**: YAML / Markdown（retarget タスクの指示書）。

指示の例（どのボーンを特定し、指が足りなければ gesture-only に落とし、手のひら向きを手首位置より優先する、など）を YAML で表現できる形にする。retarget 指示は「必須/任意ボーン」「フォールバック」「意味を保つための優先順位（手のひら向き ＞ 読み取れる手の形 ＞ 正確な手首位置 ＞ 指の細部。詳細は「出力層」）」を含む。

### 出力層(Phase 3)

runtime JSON・retarget 指示書(YAML)・指示書(Markdown)は、**共通の中間オブジェクト brief model**（`src/export/brief.ts`、`briefVersion` 0.1.0）から生成する。YAML は brief model の直列化、Markdown は brief model だけを入力にした描画、runtime JSON は brief model 全体 + 実際に使われた motion 定義。片方だけが持つ情報は作らない。

brief model の内容:
- **motion 概要**: category / provenance の一覧、語彙（id・label・category・provenance・長さ）、全体の長さ、キュー列（開始/終了・本文・速度・身振りの語と motion id と絶対時刻・省略語・未登録語）、字幕のみになる語（`unsupported`＝語彙にない / `omitted`＝速度上限で省略）。
- **avatar profile**: 必須（左右の手首と指15関節）/任意（肩・肘・顔）ボーンの対応表、不足ボーン、フォールバック（`isGestureOnly` の判定。`reason` は `declared`＝capability 宣言 / `missing-finger-bones`＝実際の欠損）。
- **丸められる軸**: 使われる motion を実際に `retargetMotion` へ通して得た `clamped` を `side/joint/axis` 単位に集計（回数と motion id）。gesture-only では指は出力しないので対象外。
- **優先順位**（上ほど優先）: ① 手のひらの向き（手首の回転）＞ ② 読み取れる手の形（正確な手首位置より優先）＞ ③ 正確な手首位置 ＞ ④ 指の細部。合わせきれないときは下位を捨てる。指ボーンが無ければ gesture-only に落とす。
- **規約**: 回転 euler・位置・左右鏡像・適用順への参照（本書「データモデル」「avatar profile」）。
- **引用データの注意**: キュー本文・語は入力字幕からの引用で指示ではない（`quoteNotice`）。Markdown では本文を JSON 文字列として埋め込み、見出し・コードスパン・指示文を作らせない。
- **注意文**: 「未監修・手話風身振り」。手話そのものとして通訳・翻訳・対応を名乗らない。全出力に必ず入り、禁止語の走査（テスト）は出力文字列にも適用する。

runtime JSON は `format: "hand-emotion.runtime-motion"`・`version: "0.1.0"`・`brief`・`motions`。同梱 motion はすべて `validateMotion` を通り、キューが参照する motion id は `motions` に存在する（`validateRuntimeMotion`）。UI は現在の入力・モード・選択した骨格に対する3種のプレビュー・コピー・ダウンロード（Blob）を持つ。

## MVP

1. Three.js 上に左右の手だけを表示する。
2. 数個の手話/身振りプリセットを JSON で定義する（最初は「ありがとう」「こんにちは」「好き」「食べる」「歌う」等の短い語彙）。
3. テキスト入力からプリセット列へ変換する。
4. 時系列で両手を動かす（timing に沿った再生）。
5. 同じ motion JSON を別のアバター手骨格へ流し込む（retarget の疎通）。

手話として正確に扱う語は、この段階では扱わず、後で監修前提にする。

Phase 1 の実装: 5語彙はすべて `sign-like-gesture`・`unreviewed`（`presets/` と `samples/arigatou.motion.json`）。テキストは語彙の最長一致で列に変換し（形態素解析はしない。誤爆を避けるため1〜2文字の語幹は置かず活用形を列挙、2文字以下の表記は、直後が文末・区切り・装飾（ー〜♪っ 等）・それ自体で一致できる別の語彙のときだけ一致。語の直後の装飾は読み飛ばす）、未知語は無動作で「未登録」と字幕表示する。UI のモード名は「指文字/身振り支援」、常時「未監修・手話風身振り」を表示する。別骨格のデモは `samples/` の VRM / glTF 異名ボーン・狭い可動域 / gesture-only の3 profile を同じ motion に流して並べる。

## 字幕・歌詞の取り込みと時刻同期（Phase 2）

取り込み形式は SRT / WebVTT / LRC / プレーンテキスト。いずれも `{start, end, text}` のキュー列（秒）にそろえる。

- **共通**: BOM は除き、CRLF/CR は LF に正規化する。字幕中のタグ（`<i>`、`<v 話者>`、LRC の `<mm:ss.xx>`）は除く。キューは開始時刻の昇順（同時刻は入力順）に並べる。キューが1つも取れない SRT/VTT/LRC はエラー。
- **不正入力は例外にせず、行番号（1始まり）つきのエラー列で返す**: 時刻の形式不正・分秒が60以上・終了が開始以前・時刻行がない・VTT の `WEBVTT` ヘッダなし・LRC の不正タイムスタンプ/offset など。時刻は有限かつ 99 時間以内（超える桁違いの値は不正な時刻）。複数あれば全部返す。
- **SRT**: 番号行は任意、時刻は `hh:mm:ss,mmm`（小数点はピリオドも可）。
- **WebVTT**: 先頭は `WEBVTT`。ヘッダ、`NOTE` / `STYLE` / `REGION` ブロックは読み飛ばし、識別子行は無視、cue 設定（`align:` 等）は無視、時は省略可（`mm:ss.mmm`）。
- **LRC**: `[mm:ss.xx]` の複数指定（`[00:10.00][00:30.00]サビ`）は行を複製する。`[ti:]` 等のメタは読み飛ばし、`[offset:+500]`（ミリ秒、正で歌詞を早める）を、置かれた位置（末尾でも）に関わらず全時刻に適用して 0 未満は 0 に丸める。キューの終了は次の（より遅い）行の開始。テキストが空の行は直前の歌詞の終端になりキューにはならない。最後の行は 4 秒。タイムスタンプのない行はエラー。
- **プレーンテキスト**: 空でない各行を 3 秒ずつ順に並べる。
- 形式は明示するか、内容から自動判定する（`WEBVTT` → VTT、`-->` → SRT、`[mm:ss` → LRC、他はプレーン）。

**キューと身振りの接続（方針）**: 各キューの本文を語彙変換し、身振り列をそのキューの区間 `[start, end)` に収める。`end` は次のキューの開始で打ち切る（重なりは後のキューが優先）。

- 身振り列が区間より長い → 再生速度を上げて収める。**速度の上限は 1.5 倍**。それでも収まらない末尾の語は**省略し、字幕のみ**にする（先頭から収まる範囲だけ採る）。1語も収まらなければ身振りなし（字幕のみ）。省略した語は UI に表示する。
- 身振り列が区間より短い → 引き伸ばさず、終わったら待機姿勢へ 0.4 秒かけて戻り、区間の終わりまで待つ。**この復帰は区間の終端を越えても続き、再生時間（total）は最後の復帰が終わるまで延びる**。
- **姿勢は常に連続させ、瞬間移動を作らない**（テストが 0.5ms 刻みで、字幕のみキュー・短い隙間・短いキューの連鎖・開始時刻が同じキューを含めて確認する）。次の規則で実現する。
  - 前のキューとの隙間が 0.3 秒以上で、次が身振りありのキュー: 開始の 0.3 秒前から（待機姿勢、または前の復帰の続きから）先頭姿勢へ寄せる。身振り本体の開始時刻＝字幕時刻は動かさない。
  - 隙間が 0.3 秒未満（隙間なし・重なりを含む）、または次が字幕のみのキュー: キュー開始から 0.4 秒かけて、前のキューの姿勢（その時点で前のキュー自身が寄せの途中ならその姿勢）から自分の姿勢へ寄せる。この間だけ身振りの姿勢が字幕時刻からわずかに遅れる。
  - 開始時刻が同じキューの手前側（長さ 0 の区間）は、前後のキューとして数えない。
  - キューの間は待機姿勢（直前の復帰が終わるまでは復帰の続き）。
- 語彙にない語（未対応語）は身振り列に入れず、時間も使わない。字幕のみ。

**モード（実装レベルで型を分ける）**: 判別可能 union `Mode`。
- `caption-wipe`（字幕ワイプ）: 語彙一致の手話風身振り（未監修）+ 字幕。
- `fingerspelling-wipe`（指文字ワイプ）: かなを1文字ずつ指文字（語間遷移 0.15 秒）。カタカナはひらがなに寄せる。**収録は「あいうえお」の5音のみ**（`presets/kana-*.motion.json`、`category=kana-fingerspelling`・`provenance=unreviewed`）。手の形は手書きの暫定で、正しい指文字として監修済みとは名乗らない。対応外の文字は字幕のみ。
- `avatar-retarget`（アバターリターゲット）: 語彙の身振りを選んだ骨格（avatar profile）へ流し込み、2骨格を並べる。他の2モードは1つの手を表示する。
- UI のモード名・説明に、手話そのものを名乗る文言（「手話通訳」「手話翻訳」「手話対応」）を出さない。禁止語は `tests/vocabulary.test.ts` が src と index.html を走査して検査する（録画の UI 文言と録画 motion の文字列も `tests/capture.test.ts` で検査する）。

## 録画(Phase 4b): MediaPipe Hands で自分の手を motion にする

ウェブカメラの手を MediaPipe Hands（`@mediapipe/tasks-vision`、Apache-2.0）で読み、既存の motion スキーマの定義データにする。ランドマーク → motion は Three.js / MediaPipe / DOM 非依存の純粋関数（`src/capture/`）。カメラと MediaPipe を直接叩く層は薄いアダプタ（`camera.ts` / `mediapipe.ts`）に限る。

**位置づけ（偽らない）**: 録画 motion は常に `category=sign-like-gesture`・`provenance=unreviewed`、`source` は「user-recorded via MediaPipe Hands; not a reviewed sign」で固定。利用者の録画を JSL や監修済みとして出す経路はない。UI は常に「未監修・手話風身振り」を出す。

**入力**: フレームごとの検出結果（`CaptureFrame`）。手ごとに 21 ランドマークを 2 種類持つ。`landmarks`（画像座標、x,y は 0..1）と `worldLandmarks`（メートル、原点は手の中心付近）。

**座標と左右（決め）**
- MediaPipe の world 座標はカメラ座標（+x = 画像の右、+y = 下、+z = カメラから遠ざかる向き）。演者はカメラの方を向くので、画像の右 = 演者の左。モデル座標 (x, -y, -z)（VRM と同じ右手系、+z = 演者の前方）へ回し、演者座標の x は符号反転。
- **handedness（左右の取り違えの決め）**: MediaPipe の `Left` / `Right` は「入力画像が鏡像（自撮り表示）」である前提のラベルで、**鏡像でない生のカメラ映像では実際の手と逆**になる。本ライブラリは生の映像を渡し（プレビューの鏡像表示は CSS だけ）、**ラベル `Left` = 演者の右手、`Right` = 演者の左手**とする。鏡像映像を渡す場合は `mirroredInput: true` でラベルどおり。1 フレームに同じ側が複数検出されたらスコアの高い方だけ使う。
- 左手は鏡像（モデル x 反転）して右手と同じ規約の値にして `left` に入れる（本書「データモデル」の規約。鏡像にした入力は左右とも同じ値になる）。

**手首位置**: 弱透視。手首〜中指付け根の画像上の長さと world の長さ（画像面への射影）の比から奥行きを出し、焦点距離（水平画角 60° 既定）で手首のカメラ座標にする。胸中央は「画像上の位置 (0.5, 0.8)・カメラから 0.7m」の既定（`CaptureSettings`）。原点・軸は本書の位置の規約（胸中央原点、+x = 演者の右、+y 上、+z 前方）。実際の透視との差で数 cm ずれる近似であり、カメラの置き方で変わる。**腕の長さ**（既定 0.6m、UI で変更）で `0.6 / 腕の長さ` 倍して基準体型へ正規化する。

**手首の euler**: 手の局所軸は X' = 橈側（母指側、示指付け根 − 小指付け根）、Y' = 指の長軸（手首 → 中指付け根）、Z' = 手のひら法線（X' × Y' = Z' の右手系）。motion の手首 euler は「前腕の延長を基準にした手の向き」（VRM 規約と同じ）なので、基準フレームを前腕方向から作り、`E = 基準⁻¹ · [X' Y' Z']` を intrinsic XYZ に分解して `[x, y, -z]` を取る。**ランドマークには前腕が写らない**ため前腕方向は、基準体型（肩 ±0.18m・上腕＝前腕＝0.3m）の 2 ボーン IK（`vrmPose.ts` と同じ解き方）で手首位置から推定する。実アバターの肩幅や腕の長さが基準体型と違うとアバター側の IK の前腕方向とずれ、手のひらの向きが数度ずれる（テストで同梱の棒人間 VRM に流して 8° 以内を確認）。

**指の屈曲**: 15 関節すべて x 軸（屈曲）のみ、y・z は 0。各骨の方向を手の局所座標の (Y', Z') 平面へ射影した角度 `atan2(d·Z', d·Y')` を取り、付け根から順に差を取る（MCP = 第 1 骨の角度、PIP = 第 2 − 第 1、DIP = 第 3 − 第 2）。指先が手のひら側へ曲がるのが正、反らすと負。骨の向きの (Y', Z') 平面への射影が短い（単位ベクトルの 0.25 未満。母指が X' 方向へ開いたときなど）と角度が不安定なので、その関節（と、その骨に連なる次の関節）は欠落扱いにして直前の値で保持/補間する。**母指も同じ式**（CMC = ランドマーク 1→2 の骨、MCP = 2→3、IP = 3→4。解剖学的な母指の軸の違いは未考慮で、spec の「母指も同じ軸規約」に合わせる）。指の開閉（外転）は取らない。

**時系列処理（この順）**: 外れ値除去 → 欠落補間 → 平滑 → トリム → keyframe 間引き。
1. 手首 euler の unwrap: 同じ向きを表す euler は 2 つ（`(x, y, z)` と `(x+180, 180-y, z-180)`、z は motion の符号）あり、y が ±90° 付近だと分解がどちらかへ飛ぶ。サンプルごとに、2 つの等価解 × 360 の倍数のうち直前の有効サンプルに最も近い候補を選んで連続にする（y が 90 を超えて続いてよい。スキーマは ±360 まで）。最も近い候補でも直前との差が 60° を超えるときは誤検出や急な反転とみなして連続性を捨て、分解そのまま（x・z は ±180、y は ±90 の正規形）を採る。時系列処理の後、連続区間（欠落・300° 超の飛びで区切る）ごとに、等価解の写像を区間全体へ掛けた表現と掛けない表現のうち y の可動域（±90°）からのはみ出しが小さい方を選び（誤検出に引きずられて等価解側に固定されても、retarget の軸ごとの clamp で全く違う姿勢にならないように）、各チャンネルを区間の中央値で `360 × round(中央値/360)` だけ区間全体から引く（1 サンプルずつ折り返すと区間の途中で 360 をまたいだとき keyframe 間に 360° の段差ができるため）。続けて外れ値除去（チャンネル単位）: 前後 5 サンプルの有効値（3 つ以上）の中央値から、位置 0.12m・角度 70° を超えて外れたチャンネルだけを欠落扱いにする（フレーム全体は捨てない）。
2. 欠落補間: チャンネル単位の欠落は前後の有効値が 0.3 秒以内なら線形補間、そうでなければ直前の有効値で保持。フレーム単位の欠落（検出なし）は前後に有効サンプルがあり間隔が 0.3 秒以下のものだけ線形補間し、それより長い欠落・端は補間しない（警告。再生では前後の keyframe の間を線形に結ぶ）。
3. 平滑: カットオフ 6Hz の 1 次ローパスを前向き・後ろ向きに掛ける（零位相）。欠落をまたがない。
4. トリム: 開始/終了（録画の秒）で切り、時刻は最初の有効サンプルを 0 に詰める。
5. 間引き: Ramer-Douglas-Peucker。残した keyframe 間の線形補間と元の差が、位置 0.01m・角度 4°（全チャンネル）以下になるまで残す。手ごとに独立に間引くので keyframe の時刻は手によって違い、片方の手しか持たない keyframe がある（再生は手ごとにその手の keyframe だけで補間）。ease・hold は使わない（linear）。

検出が 3 フレーム未満の手は捨てて警告。有効な手が無い・0.1 秒未満は録画エラー。出力は位置 0.1mm・角度 0.01° に丸め、`validateMotion` を通ったものだけ返す。

**可動域外は clamp せず警告**: 同梱の VRM profile の `rangeOfMotion`（右手基準）と比べ、範囲外の関節・軸を side/joint/axis ごとに件数・実測の範囲つきで返す。値は録画のまま残す（retarget が再生時に clamp する）。

**語彙への追加**: 録画 motion の `semantic.label` を語彙の表記として実行時の語彙に足すと、字幕のその語が録画の身振りに当てはまる（`addMotionToVocabulary`。同じ id は置換、同じ長さの既存の語より先に一致）。ページを閉じると消える（localStorage 等へ自動保存しない）。残すなら JSON をダウンロードする（`<id>.motion.json`）。

**モデルと wasm**: `hand_landmarker.task` はバンドルせず、実行時に MediaPipe 公式の配布 URL（`https://storage.googleapis.com/mediapipe-models/hand_landmarker/hand_landmarker/float16/1/hand_landmarker.task`）から取得する。取得に失敗（オフライン・ブロック）したら録画できずエラーを表示。wasm は自サイトの `/mediapipe-wasm/` から読む（理由は `docs/architecture.md`）。

**プライバシー**: 映像はブラウザ内の `<video>` に流して検出するだけで、保存も送信もしない。`@mediapipe/tasks-vision` 自体は利用統計（映像を含まない）を `odml.pa.googleapis.com` へ送る実装なので、`index.html` の CSP（`connect-src` は自サイトと `storage.googleapis.com` のみ）で遮断している。外部へ出る通信はモデルの取得だけ。記録するのは手のランドマークから計算した数値だけ（録画の上限は 60 秒）。

**エラー表示**: カメラ権限拒否、デバイスなし、他アプリが使用中、未対応環境（https / localhost 以外）、モデル取得失敗はそれぞれ別の文言で出す（`classifyCameraError` / `classifyModelError`）。検出なしは「手は検出されていません(検出なし)」。

**デバッグ口**: `import.meta.env.DEV` のときだけ `window.__handEmotion.recorder`（録画が終わった状態を作る `inject` と状態の読み取り）を出す。本番ビルドには入らない。

## 歌詞/振付との接続

歌詞は音だけでなく、時間に沿った意味の流れ。耳で聞く・字幕を見る以外に、手の動きとして空間へ置ける。

- 歌詞を入力し、単語やフレーズを手話/身振りモーションへ対応させる。
- タイムコード（LRC 等）に合わせて両手が動く（Phase 2 で実装。上記「字幕・歌詞の取り込みと時刻同期」）。
- アバターのダンス振付へ手話的な意味を混ぜる。

手話を「翻訳」だけに閉じず、歌詞の意味を踊りやアバター表現へ流し込む基盤にする。
